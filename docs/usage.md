# 使用指南

## 配置与部署

### 首次配置

启动后打开 `http://127.0.0.1:8011`，在向导或设置页填写：

| 配置 | 要求 |
| --- | --- |
| Bot Token | 必填，用于实时同步与基础发送 |
| Bot API Base URL | 可选，使用自建 Bot API 时填写 |
| API ID / API Hash | API 复制和下载重传需配置，并完成辅助账号登录 |

原生发行包自带运行环境。Windows 包解压后双击 `.exe`；Linux 包需执行 `chmod +x`。Linux 原生包要求 x86_64、glibc ≥ 2.35，不支持 Alpine/musl。

配置和运行数据保存在可执行文件所在目录：

| 路径 | 内容 |
| --- | --- |
| `config.json` | 运行配置 |
| `data/` | 数据库、日志与 session |
| `temp/` | 下载重传与临时媒体 |

目录需有写权限，迁移或备份时应保留配置和数据。

### Docker 部署

Docker 管理运行环境、监听端口和数据持久化；Telegram 凭据、代理与同步参数仍通过 Web 控制台配置。

```bash
git clone https://github.com/RRHTY/tg-channel-sync.git
cd tg-channel-sync
touch config.json
mkdir -p data temp
docker compose up -d --build
```

Windows PowerShell 使用：

```powershell
git clone https://github.com/RRHTY/tg-channel-sync.git
cd tg-channel-sync
New-Item -ItemType File config.json
New-Item -ItemType Directory -Force data, temp
docker compose up -d --build
```

已有 `config.json` 时跳过创建步骤，保留原有配置。

[docker-compose.yml](../docker-compose.yml) 挂载 `config.json`、`data/` 和 `temp/`，默认端口为 `127.0.0.1:8011:8011`。容器内通过 `TG_SYNC_HOST=0.0.0.0` 监听；`TG_SYNC_HOST`、`TG_SYNC_PORT` 仅覆盖启动监听地址，不写入业务配置。

> [!WARNING]
> Web 控制台没有内置鉴权。远程访问需使用 VPN、带鉴权的反向代理，或 Cloudflare Tunnel 配合 Cloudflare Access。不要直接将控制台暴露到公网。

### 同步模式与限制

- **实时同步**：支持多源、多目标映射，每条映射可独立设置发送身份、失败回退与重传策略。公开频道通过轮询读取，Bot 监听通过消息事件接收。
- **历史任务**：手动指定 `source_id -> target_id` 和消息范围，不按映射表批量执行。API 复制和下载重传依赖辅助账号登录，只处理账号可读取的消息。
- **JSON 导入**：需 Telegram Desktop 单聊天导出的 `result.json` 及本地媒体，不负责导出备份。目前仍有问题待修复，建议先用少量消息验证。仅恢复普通回复，不能恢复 Telegram 原生引用片段。
- **回复与链接**：回复目标需已有消息映射；`t.me` 链接只改写到目标频道已同步的消息，不保证完整还原源频道结构。
- **媒体处理**：JSON 导入和下载重传可在图片或视频末尾追加随机字节，改变基础文件哈希；不保证适用于所有查重或媒体处理链路。JSON 导入处理临时副本，不改原始导出文件。

### JSON 去重

未填写源用户名时，优先用导出文件的来源 ID 去重；缺少来源信息时按文件内容识别。移动同一文件不会重复导入，修改或重新导出内容后可能重复发送。填写用户名的导入沿用用户名去重方式，重跑时应保持来源填写方式一致。

旧版共用来源 `0` 的记录无法安全归属，不自动迁移；升级后首次重跑旧导入应核对目标频道。

## 操作与发送结果

- **历史参数**：启动前校验参数和 JSON 文件。可显式恢复当前浏览器保存的上次成功启动参数；恢复时关闭强制发送，不自动启动任务。
- **映射管理**：支持改名、编辑策略、暂停/恢复和一键填入历史同步。暂停会等待当前发送完成；公开频道恢复后从保留位置继续读取，Bot 监听暂停期间的消息需用历史同步补齐。编辑不清除去重记录。
- **去重与续传**：重跑会跳过已确认发送的消息；API 复制与下载重传的媒体组按成员检查，部分已同步时只补缺少的成员。
- **待核对发送**：回包异常、目标消息 ID 缺失或映射保存失败时保留待核对记录，阻止自动重发。应先检查目标频道或收藏夹；确认需要重发后再使用“强制发送”，可能产生重复消息。
- **连接状态**：断线会提示状态可能过期，重连后刷新状态和近期日志。

### 收藏夹账号隔离

收藏夹消息映射、待核对记录与公开频道轮询进度按已验证的辅助账号保存。同一账号重新登录可继续使用断点；换号不会读取其他账号的记录，新账号没有轮询记录时从头检查消息。

旧收藏夹记录仅迁移到本地旧会话对应且重新验证成功的账号。无法确认归属的记录保持隔离并写入警告。

## 设置字段

| 字段 | 作用 |
| --- | --- |
| 强制发送 | 忽略重复映射与断点记录，重新处理本次范围 |
| 外部来源前缀 | 在外部转发或回复消息前追加来源链接 |
| Bot 发送失败时改用辅助账号 | Bot 上传失败后切换为已登录的辅助账号 |
| 多 Bot 上传限流轮换 | 按统计窗口、阈值和冷却时间轮换额外 Bot Token |
| Debug 终端日志 | 将系统、消息、接入库日志及 Bot 收到的消息输出到终端 |
| 日志保留条数 | 限制数据库日志数量；页面展示近期记录，导出包含当前保留的全部日志 |
| 界面主题 | CLover、Sakura Pop、Mint Melody、Starlight；即时预览，保存后持久化 |
| 页面布局 | 单页或侧边栏；即时切换并保留草稿，保存后持久化 |

### 过滤规则

支持按消息类型过滤、正则替换或屏蔽，保存前检查语法。“测试当前规则”只预览草稿，不保存或发送消息；实际规则按添加顺序作用于 HTML 文本。

媒体组任一项命中屏蔽即整组跳过。实时 Bot 复制相册需要替换说明时会逐条复制，重传模式保持整组。

## 常见问题

**停止任务后为何仍显示等待？**

程序需等待当前网络请求结束，并将断点和状态写回数据库。

**下载重传需要多少磁盘空间？**

媒体先保存到 `temp/` 再上传。处理大型媒体组时，临时空间应至少接近该组总大小，并保证足够带宽。

**旧版本运行目录可以直接复用吗？**

不保证旧数据库结构或运行目录兼容。升级前备份配置和数据；必要时通过初始化向导或设置页重新配置。
